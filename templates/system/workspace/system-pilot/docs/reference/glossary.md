# ClawPilot Glossary

Complete reference of ClawPilot terminology. Use this glossary to understand the platform vocabulary across documentation, UI, and API.

## Core Concepts

| Term | Definition |
|------|------------|
| **Instance** | A running deployment of an agent with its own configuration, sessions, and workspace. Each instance has a unique slug and belongs to one blueprint. |
| **Agent** | The logical entity that processes conversations, executes tools, and follows instructions defined in its workspace files. An agent runs inside an instance. |
| **Blueprint** | A reusable template that defines an instance's default configuration: model, tools, prompt mode, and initial workspace files. Create instances from blueprints. |
| **Agent Template** | Also called **Agent Blueprint**. A shareable package containing SOUL.md, AGENTS.md, tool profiles, and configuration presets. Used to bootstrap new agents quickly from the Templates gallery. |
| **Runtime** | The `claw-runtime` process that manages all instances, handles message routing, tool execution, and lifecycle events. One runtime per ClawPilot installation. |
| **Registry** | The SQLite database (`registry.db`) that stores all persistent state: instances, sessions, messages, tasks, flows, budgets, users, and API keys. |

## Communication

| Term | Definition |
|------|------------|
| **Channel** | A communication endpoint connecting an agent to an external service. Supported types: Telegram, Slack, webhook, and the built-in Dashboard chat. |
| **Session** | A conversation thread between a user and an agent. **Permanent sessions** persist across restarts; **ephemeral sessions** are discarded when the instance stops. |
| **A2A** | Agent-to-Agent communication protocol. Allows agents to send messages, delegate tasks, and share context across instances without user intervention. |
| **MCP** | Model Context Protocol. The standard interface through which agents access tools, resources, and external services. Each tool is exposed as an MCP endpoint. |
| **Bus** | The internal event system that broadcasts lifecycle events (instance started, message received, flow completed) to all subscribers in the runtime. |

## Flows

| Term | Definition |
|------|------------|
| **Flow** | A multi-step automated workflow defined as a sequence of steps. Each step targets an agent instance and includes a prompt, dependencies, and configuration. |
| **Flow Run** | A single execution of a flow. Tracks the status of each step, captures outputs, and records timing and cost data. |
| **Flow Step** | One unit of work within a flow. Has a target instance, prompt text, optional `dependsOn` list, and an `outcome` field populated after completion. |

## Tasks and Planning

| Term | Definition |
|------|------------|
| **Task** | A trackable work item with status (backlog, in-progress, done, blocked), priority, assignee instance, and optional parent epic. Managed via the Task Board. |
| **Epic** | A high-level grouping of related tasks. Epics appear as swimlanes on the Task Board Kanban view. |
| **SITREP** | Situation Report. A structured status update generated by an agent summarizing current state, recent actions, blockers, and next steps. |

## Security and Access

| Term | Definition |
|------|------------|
| **Named API Key** | A labeled API key stored in the registry with provider, model, and usage metadata. Assigned to instances to control which LLM provider they use. |
| **Provider** | An LLM service backend (Anthropic, OpenAI, Mistral, Google, Ollama, etc.). Each provider has its own API format and authentication requirements. |
| **Auth Profile** | A stored authentication configuration for external services (GitHub tokens, cloud credentials) that agents can reference by name. |
| **Permission Rule** | A policy that grants or denies an agent access to specific tools, files, or system operations. Defined per-instance or per-blueprint. |
| **Budget** | Spending limits set per instance or per agent. Tracks token usage and cost. Triggers auto-pause and optional Telegram alerts when thresholds are reached. |

## Agent Configuration

| Term | Definition |
|------|------------|
| **Tool Profile** | A named set of MCP tools assigned to an agent. Profiles control which tools are available during conversations (e.g., "filesystem", "git", "web-search"). |
| **Archetype** | A predefined agent pattern combining a tool profile, prompt mode, and behavioral guidelines. Examples: coder, researcher, orchestrator, reviewer. |
| **Spawn Link** | A configuration that allows one agent to create new agent instances on demand, typically used by orchestrator agents to scale teams dynamically. |
| **Heartbeat** | A scheduled health check where the runtime sends a probe message to an agent and evaluates its response. Results are tracked on the Heartbeat Heatmap. |

## Workspace and Knowledge

| Term | Definition |
|------|------------|
| **Workspace** | The directory associated with an agent containing its configuration files (SOUL.md, AGENTS.md, etc.), documentation, and memory. Stored under the instance data directory. |
| **SOUL.md** | The primary identity file in an agent's workspace. Defines capabilities, principles, and personality. Injected into the system prompt when promptMode is set to full. |
| **Prompt Mode** | Controls how much workspace content is injected into the system prompt. `full` includes all standard files; `minimal` includes only SOUL.md summary lines. |
| **Memory** | Auto-managed files in the `memory/` directory of an agent workspace. Stores facts, decisions, and timeline entries. Persisted across sessions, excluded from FTS5 workspace search. |
| **FTS5** | Full-Text Search 5 (SQLite extension). Used for workspace file search (ws_search_files), global command palette search, and the search_index virtual table. |

## UI Concepts

| Term | Definition |
|------|------------|
| **Dashboard** | The web-based management interface for ClawPilot. Built with Lit web components. Accessible at the configured HTTP port (default 19000). |
| **Pilot** | The chat interface screen where users interact with an agent instance in real time. Supports markdown rendering, tool call visualization, and file attachments. |
| **Command Palette** | Global search overlay (Cmd+K) providing FTS5 search across instances, agents, tasks, blueprints, and templates. |
| **Cluster View** | The instances overview screen showing all registered instances as cards with status indicators, quick actions, and filtering. |
| **Agent Builder** | Visual canvas for configuring an agent's tools, model, prompt mode, and workspace files. Available per instance and per blueprint. |
